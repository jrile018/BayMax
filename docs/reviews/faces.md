## Finding

**MEDIUM — request identity can differ from command idempotency identity across case versions.** `services/casualty/broker.py:96-107` permits distinct case IDs with the same authored `ExerciseNeed.request_id`. `broker.py:151-159` derives the export key from `case_hash` plus `request_id`. In the pinned synthetic repro, `npc-case-001` and `npc-case-002` carried the same `request_id=exercise-med-001`; each scripted accepted review produced a different `casualty-exercise-need-*` key. A downstream consumer that deduplicates on this key alone could record the same exercise need twice when a case is versioned or represented by two case records. No actual shared-state application occurred. Root should enforce authoritative request-ID uniqueness/aliasing across cases and atomically deduplicate at the request ledger, or use a stable request-level key while retaining the distinct case/receipt hashes as audit evidence. Add a two-case regression at that integration boundary.

## Contract assessment and limits

`RightsManifest.require` checks verified status, operation-specific permission, adult-only flag and consent reference for non-synthetic sources. Private display, public demo, video, dataset publication and GitHub publication are separate permissions. These metadata strings are audit inputs; actual license and consent must be independently verified, with channel and withdrawal handling at real-image ingest. `verify_image` checks bytes against the recorded SHA256; the demo invokes it for the committed geometric SVG, whose SHA256 matches `case-001.json`. `CaseBroker.submit` accepts typed records without image bytes, so the real-image adapter must perform that byte/dimension/rights check before exposing or submitting a case. The C1 source does not establish rights for any real photo.

`DetectionResult` records normalized face boxes and provenance; `CandidateEvidence` separately records visible-cue suggestions, and no_face/occluded/failed detections abstain from visual evidence. Accepted export uses authored `ExerciseNeed` urgency/person count only after `confirm_exercise_need=True`; the photo or face score supplies neither triage nor diagnosis. `ReviewReceipt` is immutable and binds proposal, case and image hashes; `CaseBroker` is in memory and only checks a nonblank reviewer ID. Root must authenticate the reviewer, persist terminal receipts, validate authored need/node IDs against a trusted exercise catalog, and atomically apply idempotent requests. The demo's reviewer is explicitly scripted.

The fixture is a synthetic geometric SVG with a hand-authored box and makeup cue. `mock_fixture` localization counts are geometry/harness controls. No real photograph, detector execution, consented staged case, clinical label, measured learning benefit, or dispatch outcome is present at this pin. The docs disclose those gates, so their absence is not counted as a C1 regression. An actual detector's revision string alone would not prove that weights were loaded or run.
