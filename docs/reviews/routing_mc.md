## Findings

1. **HIGH — A branch during service fails instead of preserving its active commitment.** `evals/planner/mock_world.py:32` starts `service_end` empty for every new world, while `_advance_vehicle` indexes it for any preserved `phase == "servicing"` at lines 273–274. A valid known snapshot with a committed bus at shelter, a 10-second service and an unchanged reservation initializes successfully, then `advance_to(25)` raises `KeyError 'committed-bus'`. `runner.evaluate` catches the exception and records an evaluation failure, so all seeded branches from such a checkpoint can become non-rankable. The requirements explicitly include preserved active trips and commitments at the branch point. Restore a serialized service completion time (or elapsed service state) from the snapshot, validate it, and continue that work exactly once. Add a test branching mid-service and checking service count, reservation and vehicle phase. Exact repro output is in `artifacts/review/routing_mc/pr13/review.log`.

2. **MED — Closure at exact edge exit incorrectly strands a completed traversal.** `evals/planner/mock_world.py:219` treats `event.time_s <= exit` as a mid-edge closure, so an active edge that ends at `t=32` and closes at `t=32` produces `phase='stranded'`, `progress_m=100.0`, `safe_arrivals=0`. `services/routing/safety.py:57–59` and `fixtures/routing/test_search.py:66–70` establish half-open traversal intervals, allowing exact exit at closure start. Align mock physical encounter with `[entry, exit)` and cover the equality case; then the vehicle reaches the node and any later edge entry is checked separately. Exact repro output is in the same PR 13 log.

3. **MED — Product route/ledger and Monte Carlo worlds are separate, unintegrated boundaries.** `evals/planner/mock_world.py:1–6` declares hand-authored routes and a mock ledger; `evals/planner/runner.py:21–26` trusts an injected `WorldAdapter`. PR 8 provides `Graph`, `SafetySnapshot`, `candidate_routes`, and `TripExecutor` but no production ledger implementation in its pinned tree; `fixtures/routing/test_trip_faults.py:1,9–45` uses a stub. PR 13's known snapshot uses `roads`, `route_catalog`, `vehicles`, `requests`, and a simple ledger, while `TripExecutor.snapshot()` at `services/routing/trip.py:321–329` returns `trips`, `ledger`, events, time and hash. Consequently the checkpoint cannot yet prove atomic person/aid conservation through actual routing, route tracking under sampled futures, or view/replay integration. The README correctly labels this C2 work. Integration fix: adapt the root known-state schema into the actual graph, safety, executor and ledger; have candidate generation use observed information only, apply evaluator truth only in physical advancement, preserve current edge/service state, and test one shared dispatch-to-service closure scenario end to end.

Runtime measurement remains a later readiness check: search records per-call `calculation_ms` in `services/routing/search.py:56,86`, while the current MC reports do not aggregate route/replan p50/p95 (`coordination/PATHFINDING_AND_TRACKING.md:68`). This is not a defect in the reviewed source boundary.

## Verified behavior and limits

- PR 8 pinned routing fixture tests: `18 passed, 5 subtests passed in 0.06s`, exit 0 (`pr8/review.log`). The fictional graph tests exercise full-edge forecast validation and static structural disconnection versus bounded search limit. Stub-ledger tests exercise partway-edge progression, unsafe-edge stranding and rollback. They do not establish product replay or real ledger conservation.
- PR 13 pinned targeted tests: `74 passed in 0.13s`, exit 0 (`pr13/review.log`). The two focused repros above pass through those test gaps. Generated futures preserve the JSON snapshot and reuse seeds; `PolicyView` exposes observations and candidates, not latent/truth events. `runner._view_record` checks issued and received times (`runner.py:40–49`), the mock candidate builder consumes visible observations (`mock_world.py:110–175`), and results retain per-run actions, failed-run counts, separate aid metrics and conditional arrival quantiles (`runner.py:71–137`). This is a code-level information boundary for the mock adapter, not a guarantee for arbitrary injected adapters.
- `build_ensemble` labels its synthetic cases uncalibrated, validates unique seeds and time/horizon, and generates correlated zone closures (`conditional.py:79–164`). `condition_ensemble` filters compatible closures and records the authoritative receipt (`conditional.py:187–260`). It does not claim posterior probabilities. `compare_with_holdout` rejects overlapping seed sets (`runner.py:139–147`); the return value evaluates both sets separately and does not itself enforce an external policy freeze after training.
- No production authentication, network endpoint, dependency update, or credential handling is in these pinned diffs. Security and dependency scanning for the complete application cannot be certified from this review. The route graph source, geographic access links, hazard adapter, real ledger, and UI/view replay remain integration requirements described in the contract. Coverage was not measured because the cloud environment lacks the `coverage` and `pytest-cov` packages; the attempted command and exit 4 are in the saved coverage logs.

## Public boundary for integration

PR 8: `Graph(nodes, edges, version)`, `Edge(edge_id,source,target,length_m,travel_s,access,geometry,weight_source)`, `SafetySnapshot(version,known_at_s,issued_s,horizon_s,closures,safety_buffer_s,covered_edges,provenance,safe_nodes)`, `candidate_routes(graph,start,end,vehicle_kind,departure_s,safety,...) -> SearchResult`, and `TripExecutor(graph,ledger).dispatch/advance/replan/snapshot`. Dispatch takes a validated route plus loading/service and person/cargo commitments; its ledger dependency must supply transaction, commit, depart, arrival, completion, strand, ETA update and export methods.

PR 13: `build_ensemble(snapshot,seeds,horizon_s,assumptions)`, `condition_ensemble(futures,observation)`, `evaluate(snapshot,futures,policy_factories,world_factory,decision_step_s)` and `compare_with_holdout(...)`. `WorldAdapter` must supply `policy_view`, `commit`, `advance_to`, `outcome`. `MockWorld` is the only included adapter. Its snapshot fields and route catalog need an explicit conversion from the root/PR 8 records before product use.
