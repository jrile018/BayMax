# Portable AMD source publication

This change publishes source and tests from a previously separate AMD development checkout. It adds a cgroup-v2 resource sampler under `platform/tools/` and a CPU mission-to-scene adapter under `viewer3d/`. It does not publish a captured workload, mission, person, image, rendered frame, host log, private replay input, or operational handoff.

The resource sampler reads CPU, memory, I/O and pressure counters from its current Linux cgroup namespace and reports deltas over a bounded interval. Its workspace disk check now resolves the repository root from the script location, so the source has no checkout-specific default path. This is a portability change from the historical source; it was not covered by the historical run. The sampler does not establish host-wide utilization. GPU values remain unavailable until a separate authorized measurement. A generated JSON capture includes the local hostname and filesystem paths and should be treated as operational output, not as part of this source publication. The tool targets Linux cgroup v2; the presence of this source in the repository does not make Windows resource capture supported.

The mission adapter projects a caller-bound public mission envelope into the existing scene model. It requires a separately maintained `contracts.mission` package at call time and explicit trusted mission hash and source-display bindings. It checks the received geometry and identities; it does not compute a route, interpolate progress, determine safety, or turn mock replay into an accepted incident. The optional mission tests skip at collection when `contracts.mission` is absent. A skip is a dependency signal, not a passing integration test. The adapter also depends on the repository's `viewer3d.scene`; its native-render metadata test depends on existing renderer test doubles.

The original replay-adapter test source was deliberately excluded. It requires separately frozen raw OSM and multi-frame input files that are not in this source packet or the current main tree. Publishing that test alone would create a suite failure with no portable fixture. The existing `viewer3d.replay_adapter` implementation is already in main; this packet does not modify it. Private controller cache and preflight fixture templates were also excluded because their path, ownership and execution guards belong to a separate reviewed operational workflow. No binaries, packages, capture logs, receipts, leases or credentials are included.

Historical evidence and present status are distinct. The included sampler test file contains three synthetic test functions. An independent read-only review concerned the original monitor implementation; that review and its earlier test results do not validate this relocated default path. Earlier CPU and mock-native reviews concern their own exact source versions and fixtures. The historical main merge of the native/mock archive does not validate these newly published files. The payload has only undergone byte comparison, source screening and static preparation so far; no tests, imports, resource capture, render, workload, or hardware run was performed for this publication. Independent review of the exact payload is still required before it is treated as approved source.

The remaining runtime gates are unchanged. FSR startup previously failed before provider/context/dispatch or quality proof; a later Xvfb/package/display candidate has not established runtime closure, Wine compatibility or an FSR fix. The authenticated gateway has a reviewed dependency proposal, but no accepted activation or end-to-end Maps/intake/camera result. Resource samples, mock replay, source review and this publication cannot substitute for those results. Any future runtime check needs its own current ownership and execution envelope.
