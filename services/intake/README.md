# Evidence-linked humanitarian intake

This module proposes needs/access observations for a **fictional preparedness exercise**. It does not geocode, dispatch, mutate the simulator, confirm current incidents, predict outcomes or verify whether a report is true. Exact source slices plus conservative semantic guards make review possible; a human must still check meaning and veracity.

## API and effect gate

`Report(report_id, source, received_time_s, text)` uses scenario seconds and preserves source text. `parse_proposal(report, payload, provider)` strictly validates `language`, `flags`, `claims`. A claim has an ID, `kind`, category/status `label`, exact `evidence` (`start`, `end`, `quote`, Unicode character offsets), explicit quantity+unit, urgency and literal location slots. Slots are null or `{value,evidence}`. Unknown fields/coordinates/confidence, wrong spans/types, unsupported category/status, inferred counts, approximate/range quantities, cross-clause quantities and unrelated locations fail closed. Conservative English/Spanish lexical guards are not universal semantic verification; only the English fictional fixture set is evaluated here.

`ReviewStore(aliases).submit(...)` creates pending records. `edit(proposal_id,payload,editor_id,expected_revision=...)` supports source-bound corrections while pending and records revision/editor. `review(proposal_id,'accepted'|'rejected',reviewer_id,expected_revision=...,confirmations=())` is terminal. Plain acceptance and rejection emit **zero commands**. A command requires one explicit confirmation per claim, bound to the inspected revision, exact final claim values and independently mapped entity; a missing/invalid confirmation fails atomically. Confirmations retain any semantic override reason. Identical terminal retries, regardless of confirmation order, return the same record; a changed retry fails. Unknown/unmapped/conflicting/adversarial/negated claims cannot be confirmed. Qualified access and other caution flags require a stated semantic override, which does not make an actually restricted road safe or unqualified. Exact normalized reposts are deduplicated within identical source and received time; distinct later observers remain reviewable. This is a limited repost rule, not cross-source entity/incident resolution.

Aliases contain exact literal mention -> `{entity_id,entity_type:'node'|'edge',source}`. Resolution records carry alias provenance; they establish a match in the supplied exercise graph, not verified coordinates. Root must provision a trusted versioned graph manifest, derive reviewer identity from an authenticated session, display the whole report and exact final command, require the inspected revision and a deliberate action for each command, disallow background/default confirmations, persist records, and atomically apply command `idempotency_key` at the simulator ledger/known-state boundary. An RLock serializes in-memory store operations. The reviewer ID string passed to this component is data, not proof of authentication; this core is not a persistent network service.

Commands are `propose_need` (category, quantity, unit, urgency) or `propose_access_observation` (status), with report/source/received time, reviewer, revision/editors, complete claim evidence, mapped entity and idempotency key. Repeated retrieval returns the same command; downstream exactly-once application is required. No automatic dismissal/acceptance based on model score.

## Bounded official-source candidates

live_sources.py supports two registered keyless feeds: NWS active alerts by a literal two-letter area query (/alerts/active?area=XX or the documented canonical /alerts?active=true&area=XX) and the USGS all-hour earthquake GeoJSON feed. SourcePolicy pins exact HTTPS URLs, response bytes/records, timeout, redirects and a 60-second minimum poll interval. The supplied urllib_transport disables automatic redirects; BoundedSourceClient checks every target against the exact allowlist, sends a descriptive User-Agent, uses conditional headers, and respects bounded Retry-After values without automatic retry. A successful body is parsed before becoming last-good. Fresh, not-modified, throttled, stale (with last-good), and failed (without last-good) are distinct.

parse_nws_alerts and parse_usgs_earthquakes return provider-specific candidate dictionaries. They validate IDs, statuses, source timestamps, bounded geometry, duplicate JSON keys and source provenance while retaining raw SHA-256 and fetch time. NWS expires is a message deadline distinct from event ends; null geometry preserves areaDesc, UGC and affected-zone references without inventing a point. NWS changed-ID updates/cancellations retain earlier message references. USGS keeps preferred and associated IDs, millisecond times, event type, status, point/depth and magnitude. A rolling-feed disappearance is never emitted as a retraction. The candidate acceptance field means only candidate disposition (candidate_hazard, not_actual, not_earthquake, or provider cancellation/deletion); it is not EvidenceLog acceptance.

official_records.build_official_record re-extracts one provider item from hashed raw bytes and produces the complete knight26-incident-v1 record plus a VerifiedSource bound to its exact record fingerprint. Trusted application code must supply IngestionContext (verified transport, incident AOI, first-seen/accepted time and, for a correction, the prior revision and provider ID) and the frozen contract module. The context cannot come from feed JSON. The factory checks NWS prior-message references and USGS associated IDs for changed preferred IDs. It rejects an unlinked cancellation/deletion, duplicate provider IDs, unsupported polygon structure, and point or polygon coordinates outside the incident AOI. Null NWS geometry remains an area label with an explicit warning that the AOI was not spatially verified. USGS depth stays in depth_km; the contract Point has only longitude and latitude. Provider publication/observation, event validity and message expiry remain separate fields. Seven-digit controller receipt times are truncated to the contract's microsecond precision; the original receipt remains outside the record.

official_policies(contract) yields the exact NWS/USGS API and payload allowlists for root's EvidenceLog. Root must construct the trusted context, pin the frozen contract, apply records to its append-only log, and own persistence and publication. dispatcher_synopsis(snapshot) verifies the snapshot hash and returns source-linked hazard facts, times, precision, uncertainty and source health. All operational categories remain unknown and can_calculate_operational_outcomes is false. It makes no model, dispatch or completeness claim. Fetched text/metadata remain untrusted data and must be escaped in the UI. Cloud direct DNS failure receipts under /workspace/knight26/artifacts/hf/live-source/ contain no new live fetch. Controller-relayed NWS/USGS bytes are dated official snapshots; compatibility checks against their receipt URLs and hashes do not establish continuous live ingest or a published incident.
