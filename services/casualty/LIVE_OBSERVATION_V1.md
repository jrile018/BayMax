# Faces source interface v1

Source-only implementation of the reviewed faces-live-observation-v1 schema.
No tests, imports, model calls or camera operations were executed under this
assignment. Independent source review and separate bounded test execution are
required before adoption. Product/incident adoption remains PENDING.

Stable import: `services.casualty.facial_observation`. Pure functions return
recursive immutable Mapping/tuple content. Consumers serialize with
`canonical_bytes`, never `json.dumps` on MappingProxyType. Shape/fingerprint
validation does not mean authentication or permission.

```python
validate_envelope(envelope, kind=None)
validate_frame(record)
frame_fingerprint(frame)  # strict frame alone, documented digest exception
record_fingerprint(envelope)  # whole strict envelope
validate_normalized_image(frame, image_bytes)
validate_capture_receipt(record, frame)
validate_localization(record, frame)
validate_runner_request(record)
validate_execution_receipt(record, request_envelope, *, localization=False)
validate_observation(record, frame, localization_envelope)

admit_localization(localization, *, current_frame, trusted_registry, now)
prepare_visual_request(request, *, current_frame, image_bytes, localization,
                       trusted_registry, now)
admit_observation(observation, *, current_frame, localization,
                  trusted_registry, now)
validate_human_review(review, *, current_observation, current_frame,
                      trusted_registry, now)
resolve_case_bridge(*, frame, image_bytes, capture_receipt_sha256,
                    trusted_registry, now) -> (CaseRecord, observed_time_s)
```

Codec import: `services.casualty.facial_codec` exports `parse_json`,
`canonical_bytes`, `content_fingerprint`, `InvalidEvidence`. Schema and shared
vectors are byte-identical copies of reviewed controller artifacts. There are
no new dependencies. The shortest decimal codec is authored source pending
independent review and unrun binary64/JCS controls; no conformance claim follows.

Root constructs `TrustedRegistry(records, proofs, permission_epochs,
evaluation_lineage, current_frames, case_bindings)` from independently checked
private bytes, authenticated issuances and current authority. Never instantiate
it from client requests. It snapshots mappings and envelope content; root must
construct a fresh snapshot before invocation and again under intake's writer
transaction. A snapshot is not a live revocation watcher or a resource lease.

- `records`: whole-envelope SHA256 -> exact strict envelope. Request,
  capture, localization, execution, evaluation, permission and persisted
  observation records are required where referenced. Output-only and frame-only
  hashes use their documented exceptions.
- `proofs`: `(referenced_digest, role, subject_fingerprint)` -> `TrustedProof`.
  These are verified server facts, not another unsigned HTTP receipt. Each proof
  has aware UTC issue/expiry and optional exact actor identity. Roles are
  `consent` (permission subject and actor), `capture_rights` (permission subject),
  `capture_issuer` (capture receipt subject), `normalization` (full frame subject),
  `detector_issuer`/`visual_issuer`/`runtime_log` (execution receipt subject),
  `evaluation_review` and each evaluation manifest/hash field name (evaluation
  receipt subject), `evaluation_consent`/`evaluation_rights`/
  `evaluation_permission_issuer` (dedicated permission subject),
  `admitted_observation` (persisted observation subject), `care_reviewer` (full
  review envelope subject plus reviewer actor), and `typed_case_bridge`.
- `permission_epochs`: permission envelope digest -> current nonnegative safe
  integer epoch. Missing, expired, changed or withdrawn authority fails closed.
- `evaluation_lineage`: evaluation digest -> immutable `EvaluationLineage`
  with exact permission-manifest digest and nonempty `EvaluationItem` tuple.
  Root's independently checked manifest proof attests exhaustive dataset item
  inclusion; each item references capture and dedicated permission plus session.
  Both held-out use and private report retention must be currently permitted.
- `current_frames`: `(camera_session_id, arrival_id)` -> full current-frame digest.
  Admission matches dispatch revision. Human review allows only the independently
  current workflow revision to advance, preserving all image/receipt fields.
- `case_bindings`: frame digest -> `TrustedCaseBinding` containing the root's
  preexisting item-level CaseRecord, real observed time and rights-review digest.
  No synthetic Case, rights claim, annotation or time is generated by the bridge.
  It calls existing `verify_image(..., "face_detection")`, enforces exact bytes,
  dimensions, adult consented/staged photo kind and no derived exercise need.
  The `typed_case_bridge` proof key is SHA256/JCS of `{frame_fingerprint,
  case_content_hash, observed_time_s, rights_review_receipt_sha256}`; its subject
  is the frame digest. Changing time/case breaks that exact proof.

`MissingEvidence`, `InvalidEvidence`, `StaleBinding`, `PermissionDenied` are
concrete ValueError-derived exceptions. Intake keeps its reviewed HTTP 409/403
mapping and explicit unavailable feedback. Functions do not manufacture Unable
records for missing proof. Shape-valid fixtures/scripted/unavailable envelopes
remain available to presentation/test code, but cannot pass genuine admission.
All admitted observations/reviews remain operational_eligible=false.

Intake owns capture/UI/auth/storage/wrappers/transactions/cleanup. HF owns
effectful localization and visual execution. `assess_capture` orchestration is
not exported here: intake/root must preflight with `prepare_visual_request`,
invoke only a separately permitted callback, authenticate its exact completed
receipt into a fresh registry, then admit under the current writer transaction.
No import of detector runtime is required by these pure boundaries.

This version fails closed without any current media/derived retention authority.
Separately reviewed retained-evidence projections need an explicit future root
bridge; these APIs cannot silently extend expired original grants or reuse
deidentified aggregates for admission. Ordinary demo cleanup must not revoke
unrelated held-out permissions; root controls lineage-scoped invalidation and
purge. Physical raster decode/orientation/metadata verification stays in intake
normalization and HF's existing typed detector checks; a byte hash cannot prove
those facts without the root-verified exact normalization manifest.
