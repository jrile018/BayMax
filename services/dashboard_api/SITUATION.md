# Read-only Situation display

The Situation inspector reads accepted incident evidence separately from the recorded training replay. In Situation mode, constructed fire, closures, routes, and vehicles are hidden. Only accepted source Point and Polygon geometries are placed on the Paradise OSM base map. Null geometry remains an area label or unknown; positions outside the loaded base map stay in source cards and are never relocated.

Start the dashboard with --incident-publication-dir /absolute/trusted/output to read a directory owned by root integration.incident_artifacts.SnapshotPublisher. This path is a server startup option, never an HTTP query or browser payload. With no configured directory or no current.json, /api/situation returns status=unavailable and reason=No accepted incident snapshot connected. A bad or unreadable publication returns HTTP 503 with a generic reason; the endpoint does not silently use a stale or forged fallback. POST remains disabled. The saved mock preview intentionally has no Situation endpoint.

## Producer contract

The root publisher implementation is awaiting exact independent review. Do not use this path for live adoption until root approves and supplies its protected publication directory.

The root publisher writes immutable publication-<view_hash>.json and atomically advances current.json. The pointer has exactly publication_version, view_hash, publication_file, and publication_sha256 (the SHA-256 of immutable publication bytes). publication_version is knight26-snapshot-publication-v1. The publication has incident_id, cutoff_utc, mission_hash, view_hash, snapshot, projection_input, geography_binding, metadata_attestations, synopsis, and capabilities. The nested snapshot contains schema_version=knight26-incident-v1, snapshot_hash, categories, source_health, and source records. There is no top-level snapshot_hash. Optional geography binding has exactly graph_sha256, crs, origin, epoch_utc; null means no binding.

PublicationReader opens configured paths without following symlinks, caps file size, checks the pointer's exact filename and publication byte hash, then recomputes snapshot, mission, view and optional projection hashes. These hashes establish integrity, not source authenticity. Trust in accepted evidence comes from the root publisher's verified EvidenceLog and its protected output directory. A browser arrival or matching arbitrary JSON hash is never acceptance. The reader returns the nested snapshot only; it does not calculate an outcome, change a ledger, dispatch, or authorize any action.

categories are hazard, needs, closures, vehicles, stock, and capacity. A null category is displayed Unknown. An empty accepted array is displayed as no accepted current records at the cutoff. Source health is shown separately, with stale last-good source time and refresh failure reason. Unconfirmed leads receive their own section and never become constraints. Source, accepted, published, observed, validity, and message-expiration times retain UTC Z text. Message expiration is not shown as hazard end. Operational outcomes remain unavailable under incident contract v1.
