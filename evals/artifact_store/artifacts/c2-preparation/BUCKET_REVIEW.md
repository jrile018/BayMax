# Bucket adapter focused review

Status of the initial pass: **blocking gaps for a privacy-safe, replay-identifiable remote archive**. The final v2 follow-up below supersedes this status. This review was read-only against the cloud `services/artifact_store/` implementation and `evals/artifact_store/test_store.py`, compared with local `docs/research/HF_BUCKETS_INTEGRATION.md`. I did not run a live Bucket operation, install a client, or load a model.

## Findings

1. **HIGH — The pack can upload raw sensitive values despite the sanitized-only claim.** `services/artifact_store/__init__.py:42-67` rejects selected *field names* but never inspects string values, and it also accepts a top-level JSON string or list. For example, allowlisted `metrics.json` containing `{"notes":"Jane Doe at 10 Main St", "blob":"<raw audio data>"}` passes `_structured`; metadata with `privacy: {"sanitized": true, "contains_personal_data": false}` passes `_metadata` at lines 84-86. The adapter can therefore upload a broad raw report/transcript/media payload under benign keys. The contract explicitly excludes source reports, names, sensitive locations, raw audio, face and casualty imagery. Either restrict inputs to a reviewed, typed, de-identified artifact schema with upstream sanitizer evidence and explicit human review, or describe this as an allowlist plus caller attestation, not privacy enforcement. A private Bucket is still a remote copy.

2. **HIGH — Provenance and run identity are labels, not verified replay references.** `_metadata` at `__init__.py:70-92` requires seven nonempty strings but accepts `source: "x"`, `model: "y"`, `config: "z"`, and a caller-selected run ID unrelated to UTC/seed/Git SHA. The manifest hashes copied output files at lines 131-136 but does not bind source commit, model and dataset immutable revisions, solver/policy versions, or exact config/snapshot/seed to hashes or the run ID. `test_store.py:9-18` uses `@abc` placeholders, so the test does not establish replay provenance. The integration contract calls for immutable model/dataset commits and hashes of inputs/outputs, with a run-unique prefix. Require structured provenance fields with validated immutable identifiers and content hashes where appropriate, derive or verify the run ID from those inputs, and keep the exact selected configuration/snapshot in the pack.

3. **MEDIUM — A partial remote write poisons the prefix and cannot be retried.** `upload_pack` at `__init__.py:207-222` lists the prefix, writes data, then manifest. A failure after one data object leaves a partial prefix; every later `upload_pack` call sees `existing != expected` and raises at lines 208-210. `test_store.py:122-129` confirms that partial state but does not test recovery. Since Buckets are mutable/nontransactional and network failures are plausible, the adapter needs a safe retry rule: verify each existing object against the local manifest, upload only missing objects, and publish the manifest last; reject any mismatched object. Alternatively create a fresh attempt prefix and preserve a clear failed-transfer state. Never treat partial objects as a completed archive.

4. **LOW — Downloaded manifest size is unbounded before parsing.** `fetch_pack` reads and parses `manifest.json` at `__init__.py:184-189` before applying `_manifest` limits. Unlike each data file's 10 MB cap at lines 52-55, an oversized remote manifest can consume excess memory. Bound manifest bytes before `json.loads` and reject oversized input.

## Verified boundaries and limits

- `build_pack` accepts only six named structured JSON/JSONL files, rejects direct symlinks and unexpected files, records file lengths and SHA-256 hashes, and verifies the local copied pack. `fetch_pack` validates the manifest's path allowlist and hashes before renaming the staging directory into place (`__init__.py:123-166,174-199`). These checks support integrity of a pack *once the inputs are trusted*; they do not establish sanitization or the truth of provenance labels.
- Existing-prefix idempotency downloads and verifies the remote pack and compares manifest bytes (`__init__.py:201-228`). This detects ordinary collisions, but the list-then-upload path is not atomic on a mutable Bucket. Concurrent writers using the same run ID can still overwrite each other's objects; successful verification is point-in-time, not immutable storage. Use a run ID with collision-resistant uniqueness and coordinate writers if multiple uploaders can target one prefix.
- `HfBucketBackend` requires a separate client environment, caller-confirmed free private quota, an existing private Bucket, token presence, and a Bucket-capable Hub version (`hf_backend.py:21-51`). The CLI in `__main__.py` performs local pack/verify/plan only. The code does not prove live authentication, account quota, egress, or SDK call compatibility; the parent is checking the isolated client signatures. The model environment's `huggingface_hub==0.36.2` need not be changed for this offline adapter.
- The mock tests demonstrate local pack validation and in-memory transfer behavior. They are not evidence of a live Hugging Face Bucket upload/download.

## Final v2 follow-up, 2026-10-10

Reviewed exact SHA-256 bytes: `services/artifact_store/__init__.py` `4d90685679eecc03dbe5c3be00260b77a4bdeed4f9352a43c0f718f82076b159`; `services/artifact_store/__main__.py` `db9c5dd4e33c662712c10d3230075919848258e3e5ab9596b6af7a67f3ab8778`; `services/artifact_store/hf_backend.py` `886e4dc59fa66d1cb484992ee1cfb8fb62888a0c789fb6609e1cd9f3562ad3a9`; `evals/artifact_store/test_store.py` `2acd7cdcb2fab27a67846c031af065e1302ebcecd94e3d3e284479191f47f9ff`. This is a source review; I did not rerun the worker-reported 17 mock tests or perform a live transfer.

The four initial implementation findings are materially addressed:

- Typed v2 config, aggregate, and JSONL event schemas at `__init__.py:71-115` reject arbitrary text/media fields, top-level strings/lists, nonfinite values, and coordinates under unreviewed keys. Required config and snapshot files are checked at lines 202-210, 219-243. This closes the original easy raw-text upload bypass.
- Provenance now requires full 40-hex source/solver/policy and model/dataset revisions, 64-hex config/snapshot hashes, and an integer seed; included config/snapshot bytes and seed are cross-checked (`__init__.py:119-179,182-210,258-274`). The derived run ID includes UTC time, seed, provenance fingerprint, and a caller-supplied 64-bit nonce (`149-161`). This closes arbitrary provenance label acceptance and improves accidental prefix uniqueness.
- Partial retry verifies every existing object against the local manifest, uploads only missing data, then publishes the manifest (`__init__.py:301-346`). Mismatched or foreign objects are rejected. `test_store.py:168-183` covers matching and mismatched retries.
- Both local and fetched manifests are limited to 65,536 bytes before JSON parsing (`__init__.py:231-255,277-295`). The allowed file count remains six.

**Publication limits to state accurately:** The schema controls field shape; it cannot prove that an opaque hex ID is irreversibly de-identified or that numeric aggregates cannot identify a person. The `privacy` field remains caller attestation. Revision strings are checked for length and hex syntax, not resolved against actual source/model repositories. The `snapshots.jsonl` schema holds tick, event kind, opaque entity ID, and numeric values; it does not encode a complete authoritative mission state or geography. Therefore, claim verified typed artifact retrieval and integrity, not full simulator replay/restoration or independently proven sanitization. The Bucket remains mutable: list/check/upload/verify is not atomic against concurrent writers using the same prefix, so writer coordination and a unique nonce remain operational requirements. Live SDK compatibility, auth, quota, and egress were not tested in this review.

Final implementation status: **no remaining blocker for the narrowly described offline pack and mock-backed transfer**, provided publication uses the limits above. This does not approve a live Bucket upload or a full replay/privacy guarantee.
