# Incident snapshot publication v1

`integration.incident_artifacts.SnapshotPublisher(directory)` persists one trusted `contracts.incident.EvidenceLog` cutoff snapshot. Its `publish(log, cutoff_utc, *, ledger_watermark=None, in_flight_commitments=None, source_health=None, geography_binding=None, projection_request=None, synopsis=None)` method returns a defensive JSON copy of the publication. It calls the frozen `log.snapshot` and, when requested, frozen `projection_input`; it never parses source material, runs a forecast, computes an operational outcome, routes, or dispatches.

The caller must own the exact `EvidenceLog` instance and construct its verification and review context outside untrusted input. A matching `snapshot_hash` checks integrity only. This publisher rejects a dict, arbitrary source object, or `EvidenceLog` subclass as the log. It checks the returned snapshot's version, incident ID, cutoff, and hash before writing. A projection request must explicitly supply `horizon_minutes`, `model_version`, and `assumptions`; `training_assumptions` is optional. The frozen projection validator checks all values, and this publisher verifies its hash and initial snapshot hash. Every published capability remains false: `can_calculate_operational_outcomes=false`, `can_dispatch=false`. An absent resource category stays JSON `null`, meaning unknown.

## Temporal metadata boundary

`ledger_watermark` and `in_flight_commitments` are either `None` or a trusted caller's exact `{"as_of_utc": "...Z", "value": ...}` envelope. The former's value must be non-null finite JSON; the latter's value must be a list. The envelope's `as_of_utc`, and any nested field literally named `as_of_utc`, must be no later than `cutoff_utc`. The publisher copies `value` unchanged into the frozen snapshot's `ledger_watermark` or `in_flight_commitments` field and records the envelope timestamp separately under `metadata_attestations`. `None` remains `null` in both places and asserts no ledger or commitment completeness. This checks explicit timestamps, not the truth or completeness of a ledger. A trusted caller must establish that the envelope represents its actual state at the cutoff.

`source_health` is passed to the frozen snapshot validator. Stale health needs a last-good source time and failure reason; it does not replace or redate accepted facts. `geography_binding` is optional. When present it must contain exactly `graph_sha256` (lowercase SHA-256), `crs`, `origin`, and `epoch_utc` no later than cutoff. No CRS, graph, origin, unit, or edge identity is inferred. With no binding, it is `null`.

A display synopsis requires a trusted caller-created `VerifiedSynopsis(text, as_of_utc, snapshot_hash, reviewer_id)`. Its timestamp must be no later than cutoff and its hash must match the exact current snapshot. The type and digest are binding checks, not authentication of the reviewer; the caller must perform review and authentication before constructing it. It is escaped or sanitized by any later display layer.

## Canonical hashes

All hashes are lowercase SHA-256 of UTF-8 JSON with sorted keys, no insignificant spaces, original Unicode, and finite numbers (`json.dumps(sort_keys=True, separators=(",", ":"), ensure_ascii=False, allow_nan=False)`).

`mission_hash` hashes an object with exactly these keys: `publication_version`, `incident_id`, `bbox_lonlat`, `cutoff_utc`, `categories`, `revision_history`, `unconfirmed_leads`, `accepted_source_refs`, `ledger_watermark`, `in_flight_commitments`, `metadata_attestations`, and `geography_binding`. It binds accepted fact state, source revisions and geometry, incident identity and knowledge cutoff, validated timestamp attestations, supplied ledger and commitments, and explicit graph binding. It excludes source health, synopsis, and projection display choices. It is a publication identity for these inputs, not a claim that an entire mission or real-world state is complete.

`view_hash` hashes an object with exactly these keys: `publication_version`, `mission_hash`, `snapshot_hash`, `source_health`, `synopsis`, and `projection_input_hash` (JSON `null` when no projection). A stale refresh can change the view and snapshot hashes while preserving the mission hash and last accepted facts. A later correction changes the mission hash at its own cutoff; the earlier file and forecast input remain byte identical.

## Files and failure behavior

The caller chooses an explicit absolute output directory. Existing symlink path components and `..` components are refused. The publisher may create only the final directory. It writes `publication-<view_hash>.json` as immutable content, using a temporary file, fsync, and an exclusive hard link. An existing name must have identical bytes or publication fails without overwrite. `current.json` is a small pointer containing the version, view hash, filename, and SHA-256 of publication bytes. It is replaced atomically only after the publication file exists; an interrupted pointer write leaves the old pointer intact and may leave an unreferenced immutable publication. A malformed or symlink current pointer is refused. The publisher cleans only temporary files it created and never deletes another publication. A returned dict can be mutated by its caller without changing persisted bytes or a later return.

Finite JSON input limits: each metadata envelope 1 MiB; source health, geography, and projection request 64 KiB each; publication and verified snapshot 16 MiB. Synopsis text is at most 4,096 characters. The frozen incident contract imposes its own record and history limits. These caps intentionally reject very large otherwise valid evidence logs.
