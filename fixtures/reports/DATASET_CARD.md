# Fictional intake evaluation cases, version 1

These 20 authored English reports are evaluation fixtures, not accounts of real incidents. Ten concern wildfire and ten civilian recovery. The set contains medical, evacuation, water, food, shelter and access observations, including uncertainty, contradictory observations, negation, hostile embedded instructions and a repost.

`intake_cases.json` is frozen gold data for scoring. Every report has a stable ID, domain, language, exact source text and a strict proposal payload. Each populated field has a character-indexed literal evidence span. A need claim's main evidence covers its own clause; a shared place mention can occur elsewhere in the report. An absent quantity or location is represented by `null`. A vague count is never converted to an exact number. `CR10` is linked to `CR01` through `duplicate_of`; scoring expects the repost flag and preserves both report IDs.

The fixture provider echoes these authored labels as a harness control. A perfect score for it tests loading, parsing and comparison code; it does not measure AI accuracy. The deterministic baseline is a deliberately limited English pattern implementation and is reported separately. No real Qwen output, latency or readiness is represented. To score saved model output, supply a JSON list of `{report_id, payload}` records or an object with `provider` and `predictions` keys to `python -m evals.intake.run --predictions ... --output ...`. Invalid and missing outputs remain failures, and every failed case retains its raw prediction in the output. Rejected payloads receive separate bounded raw diagnostics for unsupported extra claims and false filled quantity/location slots; they receive no valid schema, claim precision, or evidence credit.

This set is small, authored in English only, and has no independent annotator agreement or real incident sampling. It is suited to contract checks and edge-case regression, not population performance estimates. Do not use these cases to tune prompts or regexes; create separate development reports for that.
